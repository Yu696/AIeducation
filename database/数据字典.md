> 数据库：`aijiaoxue`　·　MySQL 8.0.43　·　字符集 `utf8mb4` / `utf8mb4_general_ci`　·　引擎 InnoDB
> 建表脚本：`database/schema.sql`　·　样例数据：`database/data.sql`
> 责任人：杨继鑫（16组 DRI / 技术与架构）　·　对应用户故事：US-05 统一数据建模与样例数据导入

## 0. 说明

- 本字典由 `information_schema` 直接导出，与线上库结构**逐字段一致**（共 16 张表、127 个字段）。
- 全部字段与全部数据表均已填写 `COMMENT`，是 DoD 第③条“有代码注释”在数据库侧的体现。
- 外键采用**普通索引 + 注释说明**表达关联关系，**未定义 `FOREIGN KEY` 约束**：
  避免批量导入时的写入顺序依赖，并便于演示环境按需清空单表。逻辑外键在各表“索引”行标注。

## 3. 关键统计口径

> 本节是 US-04 验收标准③与评教/人次统计的**唯一口径依据**，前后端实现与测试用例必须与本节点一致。

### 3.1 督导覆盖率口径

**严格照抄（来源：`docs/API契约.md` 第 7 节）**：

> 覆盖率 = 统计周期内存在有效听课记录（`supervision.status='FINISHED'`）的开课记录数 ÷ 统计周期内开设状态为'正常开课'的开课记录数 × 100%，按开课记录（offering）去重计数，一个人次多次听课只计 1。

落地到本库的 SQL（`status` 已按 `data.sql` 使用中文枚举，契约中的 `FINISHED` 对应 `已完成`）：

```sql
-- 分子：存在“已完成”听课记录的开课记录数（去重）
SELECT COUNT(DISTINCT offering_id) FROM supervision WHERE status = '已完成';

-- 分母：正常开课的开课记录数
SELECT COUNT(*) FROM offering WHERE offering_status = '正常开课';

-- 覆盖率（百分数，保留 1 位小数）
SELECT ROUND(
  (SELECT COUNT(DISTINCT offering_id) FROM supervision WHERE status = '已完成')
  / (SELECT COUNT(*) FROM offering WHERE offering_status = '正常开课') * 100, 1) AS coverage_rate;
```

**口径要点**：

| 要点 | 规定 |
| --- | --- |
| 统计对象 | 开课记录（`offering`），不是课程（`course`），也不是听课记录条数 |
| 分子 | `supervision.status='已完成'` 的 `offering_id` **去重**计数 |
| 分母 | `offering.offering_status='正常开课'` 的记录数 |
| 排除项 | `停开`、`已结课` 的开课记录**不计入分母**；`待安排`、`已安排` 的听课记录**不计入分子** |
| 去重规则 | 同一教学班多条已完成听课记录只计 1 次 |
| 学期维度 | 按 `offering.semester` 过滤后再套用同一公式 |
| 院系维度 | 按 `offering.department_code` 过滤后再套用同一公式 |
| 精度 | 百分数保留 1 位小数（`ROUND(...,1)`） |
| 边界 | 分母为 0 时覆盖率返回 0.0，不做除零计算 |

**样例数据验算结果**（`data.sql` 导入后实测）：

| 维度 | 分母（正常开课） | 分子（已完成，去重） | 覆盖率 |
| --- | --- | --- | --- |
| 全校 | 24 | 16 | **66.7%** |
| CS 计算机学院 | 6 | 4 | 66.7% |
| SE 软件学院 | 4 | 2 | 50.0% |
| MATH 数学与统计学院 | 5 | 3 | 60.0% |
| EN 外国语学院 | 6 | 5 | 83.3% |
| PHY 物理学院 | 3 | 2 | 66.7% |
| 2025-2026-1 | 22 | 15 | 68.2% |
| 2024-2025-2 | 2 | 1 | 50.0% |

### 3.2 学生人次口径

**选定口径（二选一，本库采用 A）**：

| 方案 | 公式 | 采用 | 说明 |
| --- | --- | --- | --- |
| **A（采用）** | `SUM(student_count.student_num)`，按 `offering_id` 分组汇总 | ✅ | 明细表为准。支持一个教学班按专业拆多条，可溯源到统计日期与专业 |
| B（不采用） | 直接取 `offering.student_count` 快照字段 | ❌ | 仅作列表页快速展示的冗余快照，不作为统计口径 |

```sql
-- 口径 A：某教学班的“学生人次”
SELECT offering_id, SUM(student_num) AS student_total
FROM student_count GROUP BY offering_id;

-- 口径 A：某教师的“学生人次”合计（教师工作台 US-03）
SELECT o.teacher_id, SUM(sc.student_num) AS student_total
FROM offering o JOIN student_count sc ON sc.offering_id = o.id
GROUP BY o.teacher_id;
```

**口径要点**：

| 要点 | 规定 |
| --- | --- |
| 唯一权威来源 | `student_count.student_num`（明细表），**不是** `offering.student_count` |
| 冗余快照 | `offering.student_count` 由明细汇总得出，仅用于列表页展示；两者不一致时以明细为准 |
| 一致性约束 | `data.sql` 已保证 `offering.student_count = SUM(student_count.student_num)`（见 README 校验 ⑥） |
| 多专业拆分 | 一个教学班可有多条明细（不同 `major`），汇总时必须 `SUM` 而非取任一条 |
| 统计时点 | 每条明细带 `stat_date`，口径为**学期初选课结束后**的人数快照；跨日期取数需先按最新 `stat_date` 过滤 |
| 教师维度 | 先按 `offering.teacher_id` 定位教学班，再汇总其明细；辅导/合上教师**不计入**学生人次归属 |
| 去重说明 | 同一学生跨教学班重复计人次（本指标是“人次”而非“人数”），不做学生级去重 |

### 3.3 评教平均分口径

```sql
-- 某教学班/某课程的学生评教平均分
SELECT offering_id, ROUND(AVG(score), 1) AS avg_score, COUNT(*) AS eval_count
FROM evaluation
WHERE evaluation_type = '学生评教' AND score IS NOT NULL
GROUP BY offering_id;
```

**口径要点**：

| 要点 | 规定 |
| --- | --- |
| 参与统计的类型 | `学生评教` 单独统计；`督导评教`、`同行评议` **不混入**学生评教平均分 |
| 无效评价剔除 | 剔除 `score IS NULL`；剔除 `score <= 0` 或 `score > 100` 的越界值 |
| 是否剔除低分 | **不剔除**任何合法低分（如教学事故导致的 60 分）。若需剔除，必须另行定义规则并在此登记 |
| 保留小数位 | **保留 1 位小数**（`ROUND(AVG(score), 1)`），与 `score DECIMAL(4,1)` 精度一致 |
| 参评人次 | `COUNT(*)`，即有效评价条数，**不是**学生人数 |
| 权限过滤 | TEACHER 角色按 `offering.teacher_id = 当前用户 teacher_id` 过滤后再聚合；DIRECTOR 按本院系过滤 |
| 空集处理 | 无有效评价时平均分返回 `null`，前端显示“暂无评教数据”，**不显示 0.0** |
| 分数分布 | 分档：`<60`、`60-69.9`、`70-79.9`、`80-89.9`、`>=90`，按 `score` 区间计数 |

### 3.4 其他派生指标口径

| 指标 | 口径 |
| --- | --- |
| 课程数 | `COUNT(DISTINCT course.id)`；`status='已发布'` 参与常规统计 |
| 教学班数 | `COUNT(DISTINCT offering.id)` |
| 教师授课分布（主任工作台） | 按 `offering.teacher_id` 分组统计教学班数与学生人次 |
| 待安排听评课清单（督导工作台） | `supervision.status='待安排'` 的听课记录，关联 `offering` 取教学班信息 |
| 角色分布（管理员工作台） | 按 `sys_user.role_code` 分组 `COUNT(*)` |
| 数据可见范围 | `sys_role.data_scope`：`ALL` 全量 / `DEPARTMENT` 本教研室 / `SELF` 仅本人；DIRECTOR 是否可跨院由 `sys_config.cross_department` 控制（样例数据为 `false`） |

### 3.5 资源挂接与备课可见口径（US-07）

| 要点 | 规定 |
| --- | --- |
| 挂接去重 | `course_resource` 以 `uk_course_resource(course_id, resource_id)` 保证一门课程与同一资源只有一行；重复挂接不新增行 |
| 软解绑 | 解绑仅将 `associated` 置 0，**不物理删除**；重新挂接时复用原行并置回 1 |
| 课程详情/挂接列表 | 只返回 `associated=1` 的资源；解绑后立即不再返回 |
| 备课查看 | `teaching_resource.status='有效'`，且资源所属教学班课程存在 `associated=1` 的挂接；`offering_id IS NULL` 的院系级公共资源保持原有行为，归入“未关联课程” |
| 跨课程挂接 | 备课视图按资源自身 `offering.course_id` 分组；在某课程下挂接/解绑只控制该课程维度是否可见，不改变资源自身的开课归属 |
| 教师数据范围 | 教师可查看本人资源，以及本人任课/合上教学班的资源；修改、删除仅限本人上传的资源（owner-only） |
| 审计留痕 | 挂接/解绑写 `sys_audit_log`：`target_type=COURSE_RESOURCE`、`target_id=课程ID`、`detail` 含资源ID |
